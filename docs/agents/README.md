# Итеративная работа с агентами

Начало: [AGENTS.md](../../AGENTS.md), [STATE.md](STATE.md), текущий запрос.
Порядок одной итерации: [LOOP.md](LOOP.md). Живая очередь и команды назначения:
[BOARD.md](BOARD.md). Исходники и соседние тесты: [CODE_MAP.md](CODE_MAP.md).

## Команды

```sh
./script/agent.sh context
./script/agent.sh doctor
./script/agent.sh board
./script/agent.sh next
./script/agent.sh show ITEM_ID
./script/agent.sh new-task short-description
```

`context` показывает Git-базу, изменения и краткий контекст. `doctor` проверяет
доступность инструментов без установки и запуска приложения; точный baseline
зафиксирован в [.github/workflows/ci.yml](../../.github/workflows/ci.yml).

`board`, `next` и `show` читают приватный GitHub Project через `gh` с доступом
`project`; настройки — [.github/agent-board.json](../../.github/agent-board.json),
авторизация — существующая конфигурация GitHub CLI. Токены в репозитории не нужны.
`next` и `show` сохраняют brief в `.agent-work/current.md` с правами 600.
Они не назначают исполнителя и не запускают агента. `next` возвращает 0 при
успешном выборе, 3 при отсутствии работы, 1 при ошибке чтения, 2 при неверных
аргументах. Старый brief при ошибке или пустой очереди сохраняется как история,
но не является новой выбранной задачей.

`new-task` создаёт `.agent-work/tasks/YYYY-MM-DD-short-description.md` из
[шаблона](TASK_TEMPLATE.md), записывает дату и исходный commit, не перезаписывает
существующую карточку. Это приватный локальный черновик, не GitHub-карточка.
Заполни приёмку и перенеси нужное в draft приватного проекта по [BOARD.md](BOARD.md).
`.agent-work/` исключён из Git; не добавляй его принудительно и не отправляй в CI.

Команды работают при вызове по абсолютному пути из другого каталога.
Проверки приложения и скриптов остаются в `./script/ci.sh checks|test|build|all`.
Ни пустая очередь, ни ошибка доступа не запускают поиск произвольных новых
функций или фоновый планировщик. По отдельному поручению на исследование агент
может подготовить идеи на доске. Реализация новой фичи требует вашего явного
подтверждения конкретного предложения; подробности — в [BOARD.md](BOARD.md).

## Согласование идей

Идеи отделены от исполнения: `Approval` показывает Draft / Needs approval /
Approved / Declined, а `Status` — Backlog / Ready / In progress / Review / Blocked / Done.
До подтверждения карточка остаётся Idea. После вашего согласия с версией и границами
она становится Feature, а подтверждение сохраняется в приватном `Approval evidence`.
Для Ready дополнительно нужны приёмка и доступные зависимости. Общее «продолжай»
не одобряет новые функции; расширение согласованного объёма снова выносится на решение.

`next` пропускает Idea и Feature без Approved и evidence. Task/Bug без метаданных
согласования доступны в рамках обычного поручения; при наличии этих метаданных
проверка применяется и к ним. Скрипт не проверяет само исходное согласие:
это обязанность координатора и исполнителя.

## Проверки по изменению

| Изменение | Достаточное начало проверки |
| --- | --- |
| Только Markdown | Ссылки, пути/команды по исходникам, `git diff --check` |
| Shell/Python | Изолированные CLI regression tests, `./script/ci.sh checks` |
| Swift-логика | Соседние регрессионные тесты, `./script/ci.sh test` |
| Проект, зависимости, helper, packaging | `./script/ci.sh` целиком |
| UI, окна, клавиатура | Build/tests и native macOS проверка затронутого сценария |

Выбирай проверки по риску diff. Логи в `.build/` локальны; в приватной карточке
сохраняй команду, SHA и результат. Старый зелёный лог не подтверждает новый код.

## Запуск следующей итерации

> Прочитай AGENTS.md, docs/agents/STATE.md и docs/agents/LOOP.md. Выполни одну
> итерацию по роли docs/agents/prompts/coordinator.md: возьми подходящую Ready
> Task/Bug или явно одобренную Feature с приватной доски. Проверь актуальность,
> назначение и приёмку; для фичи — исходное согласие пользователя и границы.
> Реализуй, проверь и передай результат; обнови evidence и следующий шаг на доске.
> Сохрани существующие изменения. Если подходящей задачи нет, заверши с handoff.

Для итерации исследования:

> Изучи текущий функционал и приватную доску. Уточни несколько полезных идей без
> дублей: кому помогают, минимальный объём, приёмка, риски и открытые вопросы.
> Сохрани черновики и готовые предложения с соответствующим значением Approval.
> Представь предложения мне для решения; продуктовые фичи пока не реализуй.

Роли: [координатор](prompts/coordinator.md), [исполнитель](prompts/implementer.md),
[независимый рецензент](prompts/reviewer.md). После перерыва перечитай карточку
через `show`, сравни её с HEAD/diff и продолжай с первого незавершённого шага.
