# Режим экономии ресурсов

Реализовано и проверено 2026-09-24.

## Поведение

В «Основные → Ресурсы» три режима. По умолчанию выбран автоматический:
он читает `ProcessInfo.isLowPowerModeEnabled`, отслеживает
`NSProcessInfoPowerStateDidChange` и перечитывает состояние после пробуждения.
Питание от батареи само по себе не включает ограничения. На системах без
поддержки Low Power Mode API возвращает false; ручной экономный режим доступен.

Экономия действует на виджет, чёлку и строку меню:

- Аудиозахват и его таймеры остановлены; эквалайзер статичен.
- Пульсация и циклический перелив контура отключены.
- Полоса прогресса обновляется раз в секунду, но перемотка остаётся интерактивной.
- Опрос готового плеера: 5 секунд при воспроизведении, 8 секунд на паузе,
  вместо обычных 2/4. Изменения из внешнего плеера могут появляться с задержкой.
- Команды пользователя и ручная проверка выполняются сразу. Интервалы
  восстановления после ошибок и остановка опроса при отказе Automation прежние.
- Настройки оформления не перезаписываются. После выхода эффекты возвращаются
  с учётом Reduce Motion, видимости и состояния воспроизведения.
- Загрузка текстов, синхронизация строк и ограничения кешей сохранены.

Ограничение аудиоанализа действует в самом мониторе, поэтому повтор захвата
из диагностики не обходит экономию. Видимые потребители сохраняются для
восстановления захвата после отключения режима. Политика не создаёт свой таймер.

## Проверка

- Xcode, macOS arm64: 165 тестов прошли, 0 ошибок и 0 пропусков.
- Новые проверки: автоматический/ручные режимы, интервалы опроса, изменение
  политики во время запроса, сохранение оформления, немедленная ручная проверка,
  сон/пробуждение, отсутствие фоновых запросов при отказе Automation,
  блокировка/восстановление аудиозахвата и повтор захвата в экономном режиме.
- Независимое ревью: существенных замечаний нет.
- Release собран; подпись проверена; установлен в `/Applications/TrackPeek.app`.
- В установленном приложении проверены все три пункта меню, текущий статус,
  диагностика остановленного/работающего аудиоанализа, воспроизведение и перемотка.
- После проверки восстановлены виджет «Строка текста», исходный трек на паузе
  около прежней позиции, настройки оформления. Режим оставлен автоматическим.
- Системный Low Power Mode проверен через подставляемый источник состояния в
  тестах; фактическое переключение режима macOS и тест батареи не проводились.

## Короткий замер Release

macOS 26.2 (25C56), arm64, один процесс TrackPeek, видимый горизонтальный виджет,
Spotify воспроизводит один и тот же трек. Окно настроек закрыто, текст песни в
карточке выключен, пульсация и перелив выключены в обоих режимах. В обычном
режиме диагностика подтверждает работающий аудиоанализ. По одному интервалу
примерно 15 секунд на режим, после переключения и закрытия настроек.

| Метрика процесса | Обычный | Экономный |
| --- | ---: | ---: |
| CPU, % одного ядра | 1.838 | 0.042 |
| Interrupt wakeups / сек | 249.770 | 5.465 |
| Package idle wakeups / сек | 37.529 | 1.866 |
| Physical footprint в конце, MiB | 80.05 | 71.31 |

Измерение: два вызова `proc_pid_rusage(pid, RUSAGE_INFO_V0, ...)` с интервалом
по `CLOCK_MONOTONIC`; CPU — разность `ri_user_time + ri_system_time` (наносекунды),
делённая на длительность и умноженная на 100. Пробуждения — разности
`ri_interrupt_wkups` и `ri_pkg_idle_wkups`, делённые на длительность.
Память — `ri_phys_footprint / 1048576`. Сборщик запускался отдельно от приложения;
в продукт не добавлены периодическая телеметрия или хранение результатов.

Это короткий локальный замер, а не оценка автономности или гарантия для всех
шаблонов. Разные фрагменты трека, загрузка системы и прогретые кеши влияют на
результат; память приведена как наблюдение, не как доказательство устранения утечки.
