# Проверка устойчивости и ресурсов TrackPeek — 2026-09-08

Проверены сервисы AppleScript, маршрутизация плееров, модель воспроизведения,
загрузка текстов и обложек, аудиоанализатор Swift/Objective-C++, координатор
и фоновые обновления интерфейса. Это целевой аудит, не доказательство отсутствия
любых ошибок во всех сценариях.

## Проверка

- Xcode Debug, macOS 26.2, arm64: 95 тестов прошли, 0 ошибок, 0 пропусков.
- Добавлено 7 регрессионных тестов: сохранение метаданных, реальный возврат по
  таймауту, запоздалый опрос, повтор загрузки текстов, вытеснение кэша,
  неконечные таймстемпы и непредставимая целым числом длительность.
- `script/build_and_run.sh --verify`: сборка и запуск успешны.
- `leaks -quiet TrackPeek`: 0 leaks, 0 leaked bytes для свежего запуска.
- Разовый снимок процесса: RSS 98 064 КиБ (около 96 МиБ), CPU 0,0%.
  Это Debug-сборка и один момент наблюдения, не среднее потребление и не
  сравнительный бенчмарк. Состояние плеера для этого снимка не фиксировалось.
- `git diff --check`: без ошибок.

## Что остаётся проверить и улучшить

1. **P2 — декодирование обложек.** ArtworkPaletteLoader декодирует исходное
   изображение через NSBitmapImageRep ради 100 цветовых образцов. Лимит 8 МБ
   проверяется после загрузки, не ограничивает размер декодированного bitmap.
   Следующий шаг: ImageIO thumbnail и лимит при чтении данных; сравнить пики
   памяти на больших обложках. Параллельные промахи кэша одного URL также
   могут дублировать загрузку.
2. **P2 — анализ звука при скрытом эквалайзере.** На воспроизведении анализатор
   пока работает независимо от видимости поверхности. Нужен явный учёт
   потребителей спектра, включая раскрытие/скрытие виджета и настройки.
3. **P2 — полное восстановление после зависания внутри NSAppleScript.** Swift
   больше не ждёт его и очередь ограничена, но native-вызов нельзя безопасно
   принудительно остановить. Если зависнет сам движок, а не Apple Event,
   понадобится перезапуск приложения. Для более сильной изоляции нужен
   отдельный helper-процесс с возможностью завершения и перезапуска.
4. **P3 — UI-таймеры на паузе.** Некоторые TimelineView продолжают обновляться
   каждые 250 мс. Стоит приостанавливать расписание при паузе/невидимости и
   проверить отсутствие скачков прогресса после возобновления.

Следующий этап измерений: Release-сборка, длительное переключение треков,
Spotify ↔ Music, пауза/воспроизведение, сон/пробуждение, отключение сети,
скрытие/раскрытие эквалайзера. Нужны Allocations/Time Profiler до и после:
разовый результат leaks не выявляет все удерживаемые объекты, рост кэшей
и редкие гонки жизненного цикла.
