# Работа агентов в TrackPeek

TrackPeek — нативное macOS-приложение: Swift 6, SwiftUI, AppKit, macOS 14+.
Оно управляет Spotify и Apple Music через локальные Apple Events. Это уже
работающий продукт; исходный `SPEC.md` описывает исторический MVP.

## Вход в задачу

1. Прочитай [актуальное состояние](docs/agents/STATE.md) и запрос пользователя.
2. Выполни `./script/agent.sh context`; проверь ветку и существующий diff.
3. Выбери нужную область в [карте кода](docs/agents/CODE_MAP.md), прочитай
   изменяемые файлы и соседние тесты. Не загружай весь журнал по умолчанию.
4. Для итерации следуй [LOOP.md](docs/agents/LOOP.md), прочитай живую
   [приватную доску](docs/agents/BOARD.md) через `./script/agent.sh board`.
   Небольшое исправление не требует отдельного плана и набора документов.

Текущий запрос определяет объём работы. Исторические указания и разрешения
из `AUTONOMOUS_PROGRESS.md` относятся к своим сессиям. Доска предлагает следующие
задачи, но не поручает выполнить их все. Один запуск цикла — одна выбранная задача.
`./script/agent.sh next` экспортирует Ready Task/Bug, не занимает её и не запускает агента.

## Проверка

Команды запускаются из корня репозитория:

```sh
./script/agent.sh doctor  # Проверка окружения, без установки инструментов
./script/ci.sh checks    # Скрипты, переводы, lint, XcodeGen consistency
./script/ci.sh test      # App-hosted tests и coverage
./script/ci.sh build     # Universal Release, arm64 + x86_64
./script/ci.sh           # Все этапы последовательно
```

- Полная конфигурация — `project.yml` и `TrackPeek.xcodeproj`; `swift test`
  через корневой `Package.swift` не проверяет приложение целиком.
- После добавления/удаления Swift-файлов или изменения `project.yml` выполни
  `xcodegen generate` и включи необходимые generated changes в тот же diff.
- `script/ci.sh` использует временную ad-hoc подпись. Не меняй личный team/signing
  в проекте ради автоматической проверки. Отчёты: `.build/ci/`.
- Локальные Xcode-сборки и тесты запускай последовательно, в том числе между
  агентами: отдельный DerivedData не устраняет общий SwiftPM cache.
- `script/build_and_run.sh` останавливает запущенный TrackPeek и запускает Debug app.
  Это инструмент интерактивной работы, не стандартная проверка агента.
- Выбирай проверки по изменению; для изменения поведения добавляй регрессионный
  тест. Отличай проверенное сегодня от старого результата или ручного сценария.

## Инварианты

- `PlaybackCoordinator` владеет расписанием polling; views используют общее
  состояние, не создают собственные циклы опроса.
- Сохраняй отмену запросов и проверки поколения/source/track identity.
  Просроченная playback-команда не должна исполняться повторно.
- AppleScript выполняется в изолированном helper. Сохраняй лимиты очередей,
  IPC и кэшей, обработку timeout и завершение ресурсов.
- Сохраняй ключи предпочтений и миграции; учитывай resource-saving и Reduce Motion.
- Пользовательский текст локализуется в `Sources/Resources/*.xcstrings`
  для en/uk/ru. Правила: [LOCALIZATION.md](docs/LOCALIZATION.md).
- Автотесты используют подставные источники и изолированные preferences.
  Не переключай личное воспроизведение, permissions или login items ради теста.
- Не добавляй историю прослушивания. Диагностика не должна содержать метаданные
  песен, персональные пути или секреты.

## Совместная работа и завершение

- Сохраняй чужие изменения. В готовом worktree продолжай текущую ветку;
  не переключай её автоматически на `main` ради инструкции начала работы.
- Делегируй независимые задачи с конкретными файлами и критериями готовности.
  В общем checkout у каждого изменяемого файла должен быть один владелец.
- Автор основного изменения интегрирует результат, проверяет общий diff
  и обновляет карточку. Рецензент сообщает дефект, место, последствия и проверку.
- Репозиторий публичный, доска приватная. Внутренние карточки остаются DraftIssue,
  локальные briefs/handoff — в игнорируемом `.agent-work/`. Не переносить их тела
  в Git, публичные issues/PR или CI artifacts. В Git — только код, правила и шаблоны.
- Назначение на доске ведёт один координатор. Это не атомарный lock: после записи
  перечитай Agent/Status; при конфликте не начинай вторую реализацию.
- Перед передачей укажи результат, команды/исходы, ограничения и следующий шаг.
  Обновляй `STATE.md` только при изменении фактов проекта, а не после каждого шага.
- Git/PR: [GIT_WORKFLOW.md](docs/GIT_WORKFLOW.md). Релизы:
  [RELEASING.md](docs/RELEASING.md). Подготовка к работе сама по себе не означает
  запрос на push, merge, установку приложения или публикацию релиза.

Если пользователь просит деплой Deployer-проекта, запускай ровно `dep deploy`
из каталога проекта. Не добавляй host или флаги (включая `--revision`), если
пользователь явно их не запросил. TrackPeek собирается через Xcode.
